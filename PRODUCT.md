# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Classroom learners practicing Git with a sample web project. They are not signing in to a real product.

## Product Purpose

Teach the class how to use Git through hands-on changes to a runnable sample interface. Success means learners can practice real version-control workflows on code that is easy to inspect and modify.

## Positioning

The project is a teaching example, not an Acme product or service. The sample sign-in page provides concrete, familiar UI content for Git exercises.

## Capabilities and Constraints

- The repository must remain practical for classroom Git exercises.
- Acme and its sign-in experience are fictional sample content.
- No production authentication or account-management behavior is provided.

## Brand Commitments

Acme is placeholder branding for the lesson. Do not treat it as a real customer, company, or product claim.

## Evidence on Hand

- A static sign-in page at [index.html](./index.html).
- Tailwind CSS and daisyUI source at [src/styles/globals.css](./src/styles/globals.css).
- No real users, customers, testimonials, product metrics, or deployment evidence are available. Future work must not fabricate them.

## Product Principles

1. Keep the project understandable to Git beginners.
2. Use realistic sample UI without implying a real service.
3. Keep exercises small enough to inspect, change, compare, and revert.
4. Preserve a runnable page that makes version-control changes visible.
